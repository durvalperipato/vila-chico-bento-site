Estratégia de Sincronização BMAd Multi-Máquinas

Decisão definitiva de governança para portabilidade e versionamento do diretório _bmad/ sem atritos operacionais.

🛡️ Decisões Travadas (Locks)
  • ✔
    Versionamento In-Repo (Remover do .gitignore): O diretório _bmad/ é documentação viva e governança do projeto. Fica versionado diretamente no Git do projeto principal.
  • ✔
    Portabilidade Instantânea: Ao trocar de laptop ou clonar o repositório em outra máquina, um único git clone restaura 100% do código e 100% do contexto BMAd (specs, epics, sprint-status e forge).
  • ✔
    Atomicidade Total de Commits & Branches: Conclusões de histórias e atualizações de especificações evoluem nas mesmas branches e commits atômicos do código-fonte.
  • ✔
    Segurança por Política de Repositório Privado: O repositório no GitHub é configurado como privado, dispensando malabarismos com repositórios satélites ou git submodules.
💀 Opções Descartadas (Killed)
  • ✖
    Repositório Central Separado para Pastas _bmad:
    Causa da Morte: Cria sobrecarga operacional desnecessária, quebra o isolamento de branches do Git, exige múltiplos commits manuais a cada tarefa e gera dessincronização contínua entre código e planejamento.
